Concept Brief: Hospital System (V1 Scope & Architecture)
เป้าหมายระบบ:
ระบบโรงพยาบาลผู้ป่วยนอก (OPD) บนเว็บที่ผู้ป่วยหนึ่งคนมีข้อมูลชุดเดียว (Single Patient View) กรอกข้อมูลครั้งเดียวใช้ได้ทุกแผนก ติดตามสถานะคิวและคำสั่งตรวจแบบ Real-time พร้อม Audit Trail ตรวจสอบย้อนหลังได้ทุกการเข้าถึงและการแก้ไข
1. เทคโนโลยีและโครงสร้างพื้นฐาน (Tech Stack & Infrastructure)
•	Database & Backend Services: Supabase (PostgreSQL, Supabase Realtime, Supabase Auth, Row Level Security, Stored Procedures/RPC)
•	Hosting & Deployment: Vercel (Automated CI/CD Deployment pipeline, Serverless/Edge Runtime)
•	Frontend Framework: Next.js / React (TypeScript)
2. ผู้ใช้งาน (9 บทบาท)
•	registrar (เวชระเบียน)
•	nurse (พยาบาล)
•	doctor (แพทย์)
•	cashier (การเงิน)
•	pharmacist (เภสัชกร)
•	warehouse (คลังสินค้า)
•	admin (ผู้ดูแลระบบ)
•	director (ผู้อำนวยการ)
•	nuclear_med (เจ้าหน้าที่เวชศาสตร์นิวเคลียร์)
3. Main OPD Flow & Dual State Machine
•	OPD Flow: ลงทะเบียน/เปิด VN ➔ พยาบาลคัดกรอง/วัด Vital Signs ➔ แพทย์ตรวจ วินิจฉัย สั่งยา/สั่งตรวจ ➔ การเงิน ➔ เภสัชจ่ายยา ➔ เสร็จสิ้น
•	Payment Policy: รองรับทั้งแบบ Pre-paid (จ่ายก่อนรับยา) และ Post-paid (ตรวจก่อนจ่ายทีหลัง สำหรับเคสด่วนหรือนิวเคลียร์)
•	State Machine 2 ระดับ:
o	Macro State (visits.status): registered ➔ triaged ➔ in_doctor ➔ pending_orders ➔ pending_payment ➔ dispensing ➔ completed
o	Micro State (orders.status): ordered ➔ scheduled ➔ in_prep ➔ in_procedure ➔ result_pending ➔ completed / cancelled
4. ไอเดียหลักในการออกแบบ (Architectural Principles)
1.	Single Patient View & Read Audit: รวมประวัติ ผลตรวจ ยา ค่าใช้จ่ายไว้ในหน้าเดียวผูกกับ HN/VN โดยการดึงข้อมูลประวัติคนไข้ต้องผ่าน Supabase RPC log_access เพื่อบันทึก Read Audit Log (ใคร, เปิดดู HN ไหน, เวลาเท่าใด) ลงตารางใน PostgreSQL ทุกครั้ง
2.	Centralized Dynamic Orders: ตาราง orders รวมศูนย์รองรับ Lab, X-ray, Nuclear Imaging, และ I-131 โดยใช้ฟิลด์ details (JSONB + GIN Index) เก็บข้อมูลเฉพาะทาง และมี flag payment_type (pre_paid / post_paid)
3.	Real-time Queueing via Supabase: ขับเคลื่อนหน้าจอคิวตามบทบาทแบบ Real-time ด้วย Supabase Realtime โดยดักฟัง event จากตาราง visits และ orders
4.	Database-level Security (Supabase RLS): ใช้ Supabase Row Level Security ผูกกับ User Role / JWT Claims ใน Database เพื่อควบคุมสิทธิ์การอ่าน-เขียนข้อมูลโดยตรง ไม่พึ่งพาการซ่อนเมนูบน UI เพียงอย่างเดียว
5.	Complete Audit Trail: ใช้ DB Triggers สำหรับ Write Audit (INSERT/UPDATE/DELETE) และใช้ RPC Function สำหรับ Read Audit
6.	Simulated External Integrations: ระบบชำระเงิน (QR Payment), ยืนยันตัวตน (Health ID), และ Telemedicine ให้ทำเป็น Mock Service พร้อมติดป้าย "simulated"
5. ขอบเขตเวอร์ชันแรก (V1 Scope)
•	ทำ (In-Scope):
o	ทะเบียนผู้ป่วย (HN) & เปิด Visit (VN)
o	หน้าจอคิว Real-time ตามบทบาท
o	บันทึก Vital Signs, ประวัติแพ้ยา, โรคประจำตัว
o	วินิจฉัยโรคด้วยรหัส ICD-10
o	ระบบสั่งยา / จ่ายยา / ออกใบเสร็จ (รองรับรายการนอกสิทธิ์)
o	ระบบนัดหมายคนไข้
o	โมดูลเวชศาสตร์นิวเคลียร์ (I-131 / Imaging): ใบสั่ง ➔ นัด ➔ เตรียมสารรังสี/Decay Calc ➔ ตรวจ ➔ รายงานผล (มี Safety Checklist)
o	แดชบอร์ดผู้อำนวยการ (Director Dashboard)
o	หน้าจอเรียกดู Audit Log (สำหรับ Admin/Director)
•	ไม่ทำ (Out-of-Scope):
o	ผู้ป่วยใน (IPD / AN / เตียง)
o	Telemedicine วิดีโอคอลจริง
o	เชื่อมต่อระบบภายนอกจริง (ใช้ Mock)
o	ระบบคลังสินค้าแบบละเอียด (Stock Valuation)
o	ระบบเบิกจ่ายประกันจริง (สปสช. / ประกันสังคม)
6. คำสั่งและขอบเขตงานเบื้องหลังสำหรับ AI (Automated Backend Generation)
ให้ AI คิด ออกแบบ และสร้างส่วนเบื้องหลังทั้งหมดโดยอัตโนมัติ ดังนี้:
•	Database DDL & Supabase Schema: ออกแบบโครงสร้าง SQL, Table Schemas, GIN Indexes, RLS Policies, DB Triggers และ RPC Functions ให้เหมาะกับ Supabase PostgreSQL
•	Vercel & Next.js Configuration: ตั้งค่าสภาพแวดล้อมโปรเจกต์ โครงสร้างโฟลเดอร์ และ Environment Variables สำหรับเชื่อมต่อกับ Supabase และ Vercel
•	TypeScript Types & Validation: สร้าง TypeScript Interfaces และ Zod Validation Schemas ให้สอดคล้องกับ DB Schema
•	Mock APIs & Services: สร้าง API Services สำหรับ Simulated QR Payment, Health ID และ Telemedicine
•	Test Suite (TDD): เขียน Test Cases ครอบคลุม Edge Cases ของ State Machines และ Role-based Access Rules
•	Seed Data: สร้าง Script สำหรับ Seed ข้อมูลจำลอง (คนไข้ 50+ คน, ประวัติการรักษา, คิวตัวอย่าง)
