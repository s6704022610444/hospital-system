# ADR 0005: Governed Demographic Amendments and V1 Duplicate HN Deactivation Policy

- **Status:** Accepted
- **Date:** 2026-10-31
- **Context:** Project Hospital System (Patient Master Index Governance)
- **Primary Source Evidence:**
  - `documents/แบบฟอร์มใบต่างๆ/OPD card.jpg`: แสดงข้อมูลประจำตัวผู้ป่วยที่เป็นเอกสารทางกฎหมาย (ชื่อ-สกุล, วันเกิด, สิทธิการรักษา, PID)
  - พระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล (PDPA) และมาตรฐานเวชระเบียนโรงพยาบาล

## Context & Problem Statement
ข้อมูลในเวชระเบียนผู้ป่วยนอกแบ่งออกเป็น 2 ระดับ:
1. **ข้อมูลติดต่อทั่วไป:** เบอร์โทรศัพท์, ที่อยู่ปัจจุบัน, บุคคลที่ติดต่อได้ในกรณีฉุกเฉิน (มักมีการเปลี่ยนแปลงบ่อยตามการย้ายที่อยู่)
2. **ข้อมูลสำคัญทางกฎหมาย (Legal Identity):** คำนำหน้า, ชื่อ-นามสกุล, เลขประจำตัวประชาชน/หนังสือเดินทาง, วันเดือนปีเกิด

หากอนุญาตให้แก้ไขข้อมูลสำคัญทางกฎหมายได้โดยอิสระโดยไม่ระบุเหตุผล อาจก่อให้เกิดความเสี่ยงเรื่องการทุจริตสวมสิทธิ หรือการสับสนประวัติการรักษาระหว่างบุคคล นอกจากนี้ ในบางกรณีผู้ป่วยอาจได้รับเลข HN ซ้ำซ้อน (เช่น จำ HN เดิมไม่ได้ หรือเจ้าหน้าที่สะกดชื่อผิดตอนค้นหา) การทำระบบรวมประวัติอัตโนมัติ (Automated Merge HN) ในเวอร์ชันแรกมีความเสี่ยงสูงที่จะทำให้ข้อมูลผลแล็บ คำสั่งตรวจ และประวัติการรักษาเดิมเกิดความเสียหาย (Data Corruption)

## Decision Drivers
1. **Legal Traceability:** การเปลี่ยนแปลงข้อมูลสำคัญทางกฎหมายต้องมีหลักฐานและเหตุผลทางนิติวิทยาศาสตร์กำกับเสมอ
2. **Patient Safety & Data Integrity:** ป้องกันการแก้ข้อมูลจนผิดตัวคนไข้ หรือเกิดความเสียหายต่อประวัติการรักษาเดิม
3. **Pragmatic V1 Scope:** ลดความซับซ้อนและหลีกเลี่ยงความเสี่ยงของการเขียนคำสั่ง Relational Database Merge อัตโนมัติข้ามหลายตารางใน V1

## Decision Outcome
เลือกสถาปัตยกรรม **Governed Legal Demographic Amendments (Option B)** ร่วมกับ **V1 Inactive HN Flagging Policy (Option ข)**:

### 1. Governed Demographic Amendments
- **ข้อมูลติดต่อทั่วไป (Routine Contact Info):**
  - เบอร์โทรศัพท์, ที่อยู่: เจ้าหน้าที่เวชระเบียนสามารถแก้ไขได้ทันที โดยระบบบันทึก Write Audit Trail มาตรฐานอัตโนมัติ
- **ข้อมูลสำคัญทางกฎหมาย (Legal Identity Credentials):**
  - ชื่อ, นามสกุล, เลขบัตรประชาชน 13 หลัก, เลขหนังสือเดินทาง, วันเดือนปีเกิด:
  - **บังคับกรอก "เหตุผลการแก้ไข (Amendment Reason)" เสมอ** (เช่น มีใบเปลี่ยนชื่อ-สกุลจากที่ว่าการอำเภอ, แก้ไขเลขบัตรประชาชนตามบัตรจริง)
  - ระบบบันทึกประวัติการเปลี่ยนแปลงลงในตาราง `patient_amendments` ระบุ: ค่าเดิม (Old Value), ค่าใหม่ (New Value), เหตุผลที่แก้ไข, ผู้ทำการแก้ไข, และวันเวลา

### 2. V1 Duplicate HN Policy (การปิดการใช้งาน HN ซ้ำแทนการ Merge)
- การรวมประวัติอัตโนมัติ (Automated Relational Merge) ถือเป็น **Out-of-Scope สำหรับ V1**
- เมื่อเจ้าหน้าที่เวชระเบียนหรือผู้ดูแลระบบตรวจพบว่าผู้ป่วยมี HN ซ้ำซ้อน 2 บัญชี:
  - กำหนดให้ HN ตัวที่ถูกต้องและสมบูรณ์ที่สุดเป็น **Primary HN**
  - ปรับสถานะของ HN ที่ซ้ำซ้อนเป็น `status = 'inactive'` พร้อมบันทึกฟิลด์ `merged_into_hn = '<primary_hn>'` และหมายเหตุ
  - **กฎเกณฑ์ระดับระบบ:** HN ที่มีสถานะ `inactive` จะถูกบล็อก ไม่สามารถเปิด Visit (VN) ใหม่ได้อีก แต่ประวัติการรักษาเก่าที่เคยเกิดขึ้นในอดีตจะยังคงถูกเก็บรักษาไว้เป็นหลักฐาน ไม่สูญหาย

## Consequences
- **Positive:** ปฏิบัติตามมาตรฐานกฎหมายเวชระเบียนอย่างเคร่งครัด, ตรวจสอบที่มาของการเปลี่ยนชื่อได้ 100%, ปลอดภัยต่อความสมบูรณ์ของฐานข้อมูลใน V1
- **Negative / Trade-offs:** ใน V1 หากต้องการดูประวัติเก่าของ HN ที่ปิดการใช้งาน เจ้าหน้าที่ต้องค้นหาประวัติเดิมแยกต่างหากตามเลขอ้างอิง `merged_into_hn`
