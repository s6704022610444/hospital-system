# ADR 0008: Hybrid Clinic Exam Queue Handover and Automated Triage Fast-Track Escalation

- **Status:** Accepted
- **Date:** 2026-11-01
- **Context:** ก้าวที่ 2: ระบบงานการพยาบาลผู้ป่วยนอก (OPD Nursing Workstation) & ก้าวที่ 3: ระบบงานตรวจรักษาของแพทย์
- **Primary Source Evidence:**
  - `documents/แบบฟอร์มใบต่างๆ/OPD card.jpg`: ตราประทับสัญญาณชีพและการระบุห้องตรวจเฉพาะทาง เช่น เวชศาสตร์นิวเคลียร์ (นอกเวลา)
  - `documents/ตัวอย่างของโรงพยาบาลอื่น/โรงพยาบาลพระนั่งเกล้า/S__17145860_0.jpg`: หน้าจอระบบจริงแสดงการจัดคิวแพทย์ การส่งต่อ และการแจ้งเตือนสัญญาณชีพวิกฤต

## Context & Problem Statement
ในโรงพยาบาลศูนย์ขนาดใหญ่ การส่งต่อผู้ป่วยจากจุดคัดกรองพยาบาลไปยังห้องตรวจแพทย์มี 2 รูปแบบที่ต้องใช้งานร่วมกัน:
1. **คลินิกเฉพาะทางที่มีแพทย์เฉพาะราย (Dedicated Doctor Room):** เช่น คลินิกไทรอยด์ ห้อง 101 ต้องส่งตรงถึง นพ. ทวี ยิ่งสง่า
2. **คลินิกทั่วไปที่มีแพทย์หลายท่าน (Pooled Clinic Queue):** เช่น คลินิกอายุรกรรมทั่วไป หรือ เวชศาสตร์ครอบครัว ซึ่งมีห้องตรวจ 101, 102, 103 เปิดพร้อมกัน แพทย์ห้องใดตรวจเสร็จก่อนจะกดเรียกคิวคนไข้คนถัดไปจากคิวกลางของคลินิก

นอกจากนี้ ในกรณีที่พยาบาลวัดพบสัญญาณชีพวิกฤต (เช่น ความดันโลหิตสูงวิกฤต SBP ≥ 180 mmHg, อุณหภูมิร่างกาย ≥ 39.0 °C, หรือ SpO2 < 92%) หากผู้ป่วยต้องนั่งรอคิวปกติแบบเข้าก่อน-ออกก่อน (FIFO) จะมีความเสี่ยงสูงต่อภาวะแทรกซ้อนรุนแรง เช่น เส้นเลือดในสมองแตก (Stroke) หรือภาวะช็อก (Shock)

## Decision Drivers
1. **Dispatch Flexibility:** พยาบาลสามารถเลือกส่งเข้า "คิวกลางของคลินิก" หรือ "เจาะจงห้องตรวจแพทย์" ได้อย่างอิสระตามความเหมาะสมของเคส
2. **Clinical Safety First (Zero-Delay Critical Care):** ระบบต้องตรวจจับค่าสัญญาณชีพวิกฤตได้อัตโนมัติ และยกระดับคิวขึ้นไปอยู่แถวหน้าสุด (Priority Queue) ทันทีโดยไม่ต้องรอให้พยาบาลมากดแทรกคิวเอง
3. **Clinical Transparency:** หน้าจอคิวของแพทย์และพยาบาลต้องแสดงสัญลักษณ์กระพริบเตือนสีแดงให้เห็นเด่นชัด พร้อมระบุสาเหตุที่แทรกคิว (เช่น ความดันวิกฤต SBP 195 mmHg) เพื่อความโปร่งใสและตรวจสอบได้ (Accountability)

## Decision Outcome
เลือกสถาปัตยกรรม **Hybrid Exam Queue Engine with Automated Triage Fast-Track Escalation**:

### 1. Hybrid Queue Handover Engine
- ในแผ่นชาร์ต Electronic OPD Card ช่องส่งต่อห้องตรวจแพทย์จะมีตัวเลือก 2 ระดับ:
  - `[ 🏥 คิวกลางคลินิก (หมอห้องใดว่างเรียกตรวจได้ทันที) ]` ➔ ผู้ป่วยจะเข้าไปรอใน Pooled Queue ของคลินิกนั้น แพทย์ห้อง 101, 102, 103 จะเห็นคิวร่วมกัน
  - `[ 🚪 ห้องตรวจเจาะจง เช่น ห้อง 101 (นพ. ทวี ยิ่งสง่า) ]` ➔ ผู้ป่วยจะถูกส่งตรงเข้าคิวเฉพาะหน้าห้อง 101 เท่านั้น

### 2. Automated Triage Fast-Track Rule Engine
เมื่อพยาบาลพิมพ์ค่าสัญญาณชีพ ระบบจะประเมินเกณฑ์วิกฤตตามหลักการแพทย์ทันที:
- **Hypertensive Crisis:** SBP ≥ 180 mmHg หรือ DBP ≥ 110 mmHg
- **Severe Hypoxia:** SpO2 < 92% (หรือ < 95% ในผู้ป่วยที่มีอาการหอบเหนื่อย)
- **Hyperpyrexia:** อุณหภูมิร่างกาย T ≥ 39.0 °C
- **Critical Tachycardia / Bradycardia:** ชีพจร PR ≥ 130 ครั้ง/นาที หรือ PR < 45 ครั้ง/นาที
- **Severe Pain:** Pain Score ≥ 8/10 (ปวดรุนแรงทนไม่ไหว)

### 3. Queue Reordering & Real-time Visual Escalation
- เมื่อตรวจพบค่าวิกฤตตามเกณฑ์:
  - ระบบจะปรับระดับความเร่งด่วนของ Visit เป็น `emergency` หรือ `urgent` อัตโนมัติ
  - แทรกชื่อผู้ป่วยขึ้นมาอยู่ **"ลำดับบนสุดของคิวรอตรวจ (Top Priority)"** ทันที นำหน้าคิวปกติ
  - แสดงป้ายเตือนกระพริบสีแดงเด่นชัด:  
    `🚨 FAST-TRACK: ความดันโลหิตวิกฤต (SBP 185 mmHg) - พบแพทย์ด่วน`
  - ข้อมูลและสัญญาณเตือนนี้จะซิงค์ไปยังหน้าจอห้องตรวจแพทย์แบบ Realtime ทันที

## Consequences
- **Positive:** รองรับทั้งการไหลเวียนคิวแบบคลินิกทั่วไปและคลินิกเฉพาะทางได้อย่างสมบูรณ์แบบ
- **Positive:** ป้องกันการเสียชีวิตและภาวะแทรกซ้อนรุนแรงของผู้ป่วยได้อย่างมีประสิทธิภาพตามมาตรฐาน JCI และ HA ของโรงพยาบาล
- **Implementation Note:** ติดตั้ง Fast-Track Rule Engine ใน `src/lib/triage/triage-service.ts` และเชื่อมโยงกับการจัดเรียงคิวใน `app/dashboard/nurse/page.tsx` และ `app/dashboard/doctor/page.tsx`
